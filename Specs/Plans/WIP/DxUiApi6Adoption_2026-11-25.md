# RedTilde DxUi API 6 adoption

**HOLD.** RedTilde ships API 5 at the exact commit in [the consumer lock](../../../Dependencies/DxUi.lock.json).
RedTilde maintainers own adoption after DxUi publishes and qualifies the interfaces they use.

The [v1.0 delivery record](../Done/V1ReleaseReadiness_2026-11-21.md) transferred API 6 adoption and its
paired performance study to post-1.0 work. [RedHome convergence decision D20](https://github.com/RedSalamanders/RedHome/blob/a4fa9486cb36ba82554c336983b233b8cbf98bf9/Specs/Plans/WIP/Convergence_2026-11-17.md#decided)
assigns the exact consumer pin and its qualification to this product. The separate dictionary and spell-checking
plan owns only its own producer dependencies.

## Implementation

1. Select a qualified exact API 6 revision from the [DxUi consumption contract](https://github.com/RedSalamanders/DxUi/blob/main/Specs/Build/Build_ToolchainAndConsumption.md).
   Review H-01 and H-02 for the consumer ABI and failure host. Check the clock supplied by RedTilde when attaching
   embedded views and every other public API 6 migration that applies to its native and embedded host paths.
2. Apply the public restore, native policy, neutral triplet property and provenance interfaces as applicable
   under CV-5-06 and CV-6-04. Preserve the existing root commands and refuse an incompatible pin. Record
   the disposition of the H-05 logging and H-14 posted-payload interfaces in the consuming code.
3. Restore the exact pin and keep the archive, headers and native build policy from that same revision.
   Verify the HWND Alt+Enter policy delivered in [DxUi #331](https://github.com/RedSalamanders/DxUi/pull/331),
   then exercise device loss, hidden capture, input, document state and restore from the existing product entry points.
4. Reconcile the [toolchain](../../Build/Build_Toolchain.md), [architecture](../../Core/Core_Architecture.md)
   and [validation](../../Testing/Testing_Validation.md) contracts with the migrated consumer.

## Acceptance

- Compile the six standard profiles and retain the exact archive, header, policy, compiler and pin identities.
- Run affected x64 regressions and the admitted native x64 and ARM64 Release regression and package checks.
  Keep separately scheduled desktop tests and their source-bound outcome in the
  [run-evidence contract](../../Testing/Testing_RunEvidence.md) workflow.
- Compare the current shipping API 5 baseline and the API 6 candidate in the required quiet-host paired study.
  Use the [performance procedure](../../Testing/Testing_Performance.md) and bind every result to its own source.
- Record the published pin and the verified scope here before archiving this plan.
