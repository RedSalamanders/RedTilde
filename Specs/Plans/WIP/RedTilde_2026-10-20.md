## Decisions and implementation slices

1. Use native DxUi ControlHost with the `RichTextEditor` from [DxUi PR #89](https://github.com/RedSalamanders/DxUi/pull/89).
   Initial experimental SHA: `29fc7897b21db3cd1d27f7ec52d6756fe9af36c0`, API revision 4. PR was draft/open when inspected.
   Pin movement requires another reviewed consumer change; no sibling repository is modified.
2. One editable source/history. View mode changes are presentation changes. Split mirror is read-only.
3. Quiet document bar, compact formatting row, optional outline and contextual tools; no imitation of Word's
   permanently expanded ribbon. Use source metadata for headings/navigation and public semantic commands.
4. Native images, inline/display mathematics and supported flowchart/state/class diagrams use DxUi. The
   read-only inspector uses the same math engine. No embedded web runtime is introduced.
5. Independent UTF-8 storage, versioned local preferences and crash diagnostics follow the Red-family pattern;
   never import another application's settings engine or crash globals through an unsupported dependency.

## Open gates and dependency limits

The pin is an experimental preview, with 65,536 source units, bounded math/flowchart/state/class support and upstream D4c
performance HOLD. Full Mermaid/LaTeX conformance, larger documents, physical IME/AT and final resource/platform
qualification are not established by adopting the API. Math/diagram/recovery continuation has its own acceptance
checks above. Conditional external-write protection remains a separate hardening gate. Do not mark S6 or this
plan complete while any required gate remains.
