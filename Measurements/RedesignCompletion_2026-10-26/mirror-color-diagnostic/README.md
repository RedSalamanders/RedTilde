# Mirror color feature-removal diagnostic

This packet preserves a fixed 16-process, two-block diagnostic comparing the full colored mirror (A) with a feature-disabled counterfactual (B). The counterfactual removes the mirror's Markdown analysis profile and rendering setup calls. It is an attribution experiment, not a product configuration to ship.

The serial schedule was Compose block 0 ABBA, Compose block 1 BAAB, Split block 0 BAAB, and Split block 1 ABBA. It used eight processes per variant, 64 measured edit cycles after two warmups, and the `redtilde-completed-native-v2` fixture (693 source units). Both views used hardware rendering, 144 DPI, and 2160 × 1350 pixels. The full variant completed 46/46 Editor cases. Each of the two separately retained disabled-variant characterization attempts completed 44/46; both failed the same two feature-dependent assertions.

The raw summary reports disabled-versus-full owner CPU changes of −0.629579% for Compose and −9.885898% for Split. These are descriptive two-block values from this feature-removal diagnostic. They are not an acceptance result, a causal allocation measurement, or evidence that removing mirror coloring is safe to ship. No A/A arm or host observer was included. Native records report hidden completed frames; physical presentation and input were not verified.

The source maps bind the two admitted roles to the same DxUi SDK commit and show one source-file difference: `RedTilde/Application.Chrome.cpp`. The disabled variant removes only `SetMarkdownAnalysisProfile(RichMarkdown)` and `SetMarkdownRenderingEnabled(true)` for the mirror. Role-specific executable, PDB, build receipt, source and compiled-source hashes are recorded in `public-declaration.json`.

The initial common-header CRLF mismatch refusal is preserved separately in `header-admission.json`; no timed processes ran before canonical header bytes were restored. The two disabled test attempts, their distinct binary/source identities, and their failed case names are separately listed in `negative-attempts.json`. Literal harness run IDs are represented there by hashes because they contain local process IDs. The original private declaration is not copied because it contains local absolute paths; its exact SHA-256 is retained in the public declaration and report index.

Each native JSON under `reports/` is byte-for-byte copied from its retained process report. `summary.json` is also an exact byte copy. `report-index.json` binds all 16 report paths and hashes to process ordinal, view, block, slot, role and executable hash. This packet makes no allocation-ownership claim; process memory snapshots are whole-process observations.

Lead replay passes 316 checks over all 16 raw report hashes, 144 per-process metrics, 24 block effects and 12 descriptive percentage changes. Independent read-only replay separately matches the raw sample medians and both block effects per row. The preserved replay and source digests are in [root-replay.json](root-replay.json).
