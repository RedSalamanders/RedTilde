# Historical 2f startup phase diagnostics

This is a derived public summary of two separate eight-process diagnostics, not a performance acceptance packet. `startup-phases.json` gives all 16 successful slot names, exact trace byte lengths/SHA256 values, record counts, source/build identity references, and arithmetic means of exactly two processes per group. Every repeated phase uses its first occurrence in each process. The original 20-row and controlled 12-row reporter tables were checked against the raw JSONL arithmetic. The cohorts are not pooled.

The original baseline/candidate first ApplyTheme comparison is about 27 MiB higher before the first complete frame. The same-candidate controlled off/on experiment defers that early initialization when the bypass is enabled. Its final private means do not show a consistent reduction: Compose **46,868 to 47,482 KiB**, Split **47,356 to 46,902 KiB**. First-frame configured-format counts change **12 to 11** and **9 to 8**, respectively. These observations do not attribute retained bytes or prove an optimization benefit.

The trace opens its output handle before the first record, enumerates threads, and synchronously writes and flushes each phase. That observer work is included in the process state. Concurrent SDK validation/builds and possible baseline builds were declared; no quiet or exclusive host was established. No CPU timing is emitted. All terminal startup hosts report **1924 by 1170 physical pixels**, whereas the primary paired scenario is nominally **1440 by 900 DIP**. Startup DPI is not emitted, so matched viewport geometry cannot be claimed. Exact source revision, source selection, and editor/footer geometry are also not emitted.

The first controlled attempt is retained as a failure: the root reported process exit 2, no trace was created, and stdout/stderr are empty. There is no captured exception or HRESULT to reconstruct. The separate retained Win32 diagnosis observed an absent variable as length 0/error 203 and a .NET null/empty-set entry as length 0/error 0 with the name still present. The repaired helper uses explicit 0/1 and the runner restores true absence through Win32 deletion. The failed files, diagnostic record, preservation manifests and source-patch references remain hash-inventoried; none is rewritten or converted into a successful run.

Origin paths are relative to the opaque `private-approved-workspace` alias, not repository paths or locations included in this packet. No identifying absolute paths, user/machine/desktop data, raw source patches, native traces or binaries are copied here. Source and binary identities are quoted from private metadata; binaries were not rehashed for this summary. This supports private integrity review and cannot independently replay absent private inputs. The instrumented historical source is not the current production candidate. No causal, CPU, physical, final-source, policy or performance-acceptance claim is made.
