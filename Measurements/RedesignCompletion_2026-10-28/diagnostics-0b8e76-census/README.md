## SDK findings

In Default WARP mode, clean composition-enabled frame tails are dominated by the blocking Map wall interval (about 0.8–1.0 ms in the two-process per-window summaries); the Compose interval itself is roughly 0.01–0.02 ms. Dirty tails share wall time between Prepare (about 1.2–2.2 ms) and Map (about 0.8–1.6 ms where composition is enabled). CallingThread mode's Map wall interval is much longer on composition-enabled paths: about 5.7–6.4 ms clean and 6.3–7.5 ms dirty. These are wall intervals in a diagnostic WARP run, not GPU duration or causal evidence.

All windows rank their own 40 frames by complete-frame QPC; p95 is nearest-rank 38/40 with chronological ties. Largest same-factor within-cell process p95 spread: MultilineGridDistinct/Dirty/On/CallingThread/compose-only (block1-slot03 vs block2-slot13) has process-level medians 10.1161 vs 8.7398 ms (B−A -1.3763 ms). Across each process’s two repeated windows, the same-ranked Map medians are 7.4955 vs 6.5811 ms (B−A -0.9144); Prepare medians are 2.5682 vs 2.1172 ms (B−A -0.4511). Ranked-frame owner-thread cycles A/B are [5041496, 3708168]/[4425732, 4375631]; owner-thread kernel 100ns deltas [156250, 0]/[0, 0]; user 100ns deltas [0, 0]/[156250, 0]. Window-wide main/process raw counters are also in `sdk-largest-replicate-spreads.csv`; timer-off interior boundaries stay blank. These repeated-window values co-occur and do not establish a cause. The 8 windows and 40 frames per window are repeated observations inside one process. Each factor cell has two fresh-process replicates; no pooled N or policy acceptance is claimed. The two MultilineGrid smoke processes are separate. `sdk-windows.csv` includes same-ranked-frame CPU data and probe brackets; `sdk-largest-replicate-spreads.csv` adds the repeated-window Map/Prepare wall intervals and owner-thread/main-thread/process raw CPU deltas for the ten largest process-replicate p95 differences. Timers Off has no inner Map/Prepare boundaries. Zero coarse CPU times are retained as valid, cycles are not converted to time, and CPU query QPC brackets include query wall/preemption/endpoint costs. The host observer sampled 1,195 times across 34 slots; this does not establish a quiet host. Controls/policy review remains open.

## RedTilde census findings

`app-census-processes.csv` lists all eight processes using only side/view, source and executable hashes, raw census totals/categories, and the primary-final-to-entry setup brackets. `app-census-comparisons.csv` retains all 16 exact side/view metric pairs and byte deltas. `app-mapping-rollup-sanitized.csv` retains the mapping comparison totals grouped by memory type and safe labels: module basenames, `FontCacheA`, `FontCacheB`, and aggregated remainder labels. `app-census-smoke-separate.json` holds the independent four-cycle smoke, excluded from eight-process comparisons.

These are descriptive, not ownership conclusions. Setup overhead was measured between primary final and observer entry; this is not an untouched frozen-process sample. MEM_PRIVATE committed bytes are not process-private bytes or allocator ownership. Mapping identity is incomplete, module RVAs do not imply equal code across different executable identities, and no heap walk was collected. Two processes per side/view do not establish a statistical or policy pass.
